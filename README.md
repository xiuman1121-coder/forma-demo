# Forma — Creative Workspace Demo 0.2

在原 Forma Demo 上增量修改，保留品牌视觉、Project / Creative Brief / Creative Direction / Campaign Assets / Version 模型与 provider 接口。主交互改为 Chat + 可平移缩放的节点画布，无后台、认证或在线模型服务。

## 运行

需要 Node.js 18+，无需安装依赖。

```sh
npm start
```

打开 http://127.0.0.1:4173 。`npm run check` 检查所有应用模块的语法。

## Happy Path

1. 首页选择 **Explore NOMA sample**，直接进入 Workspace。预置产品、Fellow / Aesop / Patagonia 网站来源，以及用户和 Agent 对话。
2. Agent 自动在同一画布生成 Understanding / Creative Insight 与三个 Direction；顶部 Sources / Insight / Directions / Outputs 仅移动视角，不是步骤或独立页面。
3. Chat 输入：`I like the idea of Coffee Anywhere, but use the more premium visual language from Designed for the Ritual.`，观察 Coffee Anywhere 卡片变化。
4. 点击任一方向的 **Develop this direction**，在画布右侧展开 Hero / Product / Social。建议演示 Designed for the Ritual。
5. 点击卡片的 `+`，或 Shift-click 多选 Product、Direction 02、Reference: Aesop。Chat 显示 **Using as context**。
6. 输入 `Create another KV from these.`，新增 KV 并保存所选对象 ID、请求文本和方向快照。
7. 点击素材 **Review & iterate**，输入反馈生成 V2，切换 V1/V2，再返回 Creative workspace。

新建空白项目不再显示 Brief Form；可以直接说需求、粘贴 URL，或上传产品/参考图。新输入通过轻量规则形成初始结构，未知信息标记为待澄清/假设。

## 真实交互

- 自然语言输入、URL Source 卡片、产品图/参考图上传；图片直接拖到画布作为 Reference。
- 每次最多选择 4 张 JPG/PNG/WebP，每张最大 5 MB；上传图保存在浏览器，不上传到外部服务。
- 卡片拖动、单选、Shift 多选、`+` 增减上下文；Chat 上下文标签可移除。
- 拖动画布空白处平移，滚轮平移，Ctrl/Command + 滚轮缩放，缩放按钮、Fit all 与区域定位。
- 卡片获得键盘焦点后可用方向键移动，Enter / Shift+Enter 选择。
- 对话历史、输入草稿、节点位置、视角、选择、素材与版本保存在原 localStorage 项目中；刷新/详情返回可恢复。
- Direction 的 Built from、方向精炼、展开素材和基于选择新增 KV 的完整交互成立。
- 继续复用素材详情、自然语言反馈规则、版本切换、PNG 下载。重复展开会保留原素材与版本，新增一组素材；方向快照避免之后的修改改变旧素材归属。

## Mock 与边界

- 无真实 LLM、图片生成 API、网页 crawling 或 multimodal orchestration。
- Sample Understanding / Insight / Reference signals 是明确的预设创意假设；URL 仅作为来源保存，不读取网页。
- Chat 使用简单意图匹配，支持示例方向组合、展开方向与 another KV。任意复杂输入会保存为 context 并说明当前支持的操作。
- 选中对象真实记录为上下文；额外 KV 使用所选 Direction 和本地构图，不语义分析参考图。
- Campaign 使用静态摄影：Hero 建立产品形象、Product 展示材质近景、Social 呈现 morning ritual。统一方向文案与色调；不是实时生成。
- Moodboard 复用原图与细节裁切。上传自有产品时，仍采用首张图进行本地组成，不具备真实多场景生成能力。
- 反馈仍是原规则：放大、暖色、文字减少、背景混色与社交裁切。未支持请求会说明图像没有改变。
- localStorage 容量有限，存满时提示；没有跨设备同步。仅保存一个当前项目，新建/打开 Sample 会替换当前项目。
- 轻量 DOM 节点画布支持无限方向平移，但不包含连线编辑、图层、协作或完整设计编辑能力。

## 真实 Agent 工作台（本机个人版）

运行 `npm start`，打开 http://127.0.0.1:4173/studio 。首页“开始创作”也进入此工作台，NOMA 示例继续保留原有演示流程。

### 独立 Planning 模型对照入口

生产任务继续使用 GLM + Seedream。独立命令只重新运行历史任务的 Planning，不执行图片生成，也不改项目、对话或作品。它使用生产 Planning 的同一份 System Prompt、原始需求和所选图片；即使历史任务在生产中因“先不要生图”而绕过 Planning，也可以通过该命令单独比较两家规划输出。GPT 使用 OpenAI Responses API 的图片输入及严格 JSON Schema；GLM 保持生产请求格式。两家输出约束不完全相同，评估时应将格式合规与规划内容分开。

在本地 `.env.local` 中加入 `OPENAI_API_KEY=...` 和明确选定的 `OPENAI_PLANNING_MODEL=...`；GLM 对照继续使用已有的 `ZHIPU_API_KEY`。不要把密钥粘贴到终端参数、测试样本或版本库。运行 Mock 自动测试无需任何真实密钥：`npm test`、`npm run check`。

真实单次 Planning 请求必须显式传入提供方、历史 job ID 和 `--allow-paid`：

```sh
node scripts/compare-planning.mjs --provider glm --job-id <UUID> --allow-paid
node scripts/compare-planning.mjs --provider gpt --job-id <同一UUID> --allow-paid
```

每条命令最多发送一次规划模型请求，不自动重试，也不会请求 Seedream。结果写入本机 `.private/planning-comparisons/`，文件权限仅允许当前用户读取；记录模型原始文字回复、解析后的 JSON、耗时、token 用量和输入图片哈希，不保存图片 base64、请求头或 API Key。模型回复可能含有用户需求内容，应把这个本地目录视为私有测试数据。OpenAI API 的实际费用以供应商账单为准，此独立入口尚未连接 Forma 的人民币预算账本；因此必须在明确允许单次付费测试时才运行。
# 固定账号演示部署

本地运行默认只监听 `127.0.0.1:4173`。需要登录时，在交互终端运行 `npm run configure-login`，输入固定邮箱和密码（至少 12 位）；脚本只将密码的 scrypt 哈希和随机会话密钥写入 `.env.local`。没有注册入口。重启服务后，未登录访客不能读取项目、接口或图片。

公网部署还需要在 `.env.local` 设置 `FORMA_PUBLIC_ORIGIN=https://你的域名`，并在同一台服务器上使用 HTTPS 反向代理转发到 `127.0.0.1:4173`。服务仍只监听本机；如果固定账号配置不完整，服务会拒绝启动。共享账号的访客看到同一工作区、共用应用内 ¥80 预算；智谱和火山的实际费用由服务器 API Key 对应账号支付，需在各供应商后台核对。当前预算账本是估算及请求预留，不是供应商账单。
