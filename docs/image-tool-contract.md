# 图片工具统一契约（待审阅草案）

状态：**完整契约仍是待审阅提案；其中字段对齐、停止隐式补参考图、独立比例参数已作小范围实现（2026-10-14）**。适用范围是 Agent 调用 `create_image` / `edit_image`，后端接收参数、调用 Seedream、保存作品这条链路。本文件描述最终拟采用的规则；当前实现仍可能与其余条款不同。

## 一、分工与不可变原则

- Planning 决定本轮是否生图、创建还是修改、目标作品、可用素材及其角色，并绑定用户或已选方案要求的比例。它不写最终生图提示词。
- Agent 决定画面设计、是否增加设计文字、准确文案和版式，并调用对应工具。它只能引用本轮绑定的素材与目标作品。
- 后端依据同一契约验证参数、解析素材文件、把比例映射为 Seedream 尺寸、按固定格式追加文字指令和已确认的商品外观事实。它不得依据关键词猜测有字／无字，不得把讨论稿或其他方案塞入提示词，不得替 Agent 发明画面或文案。
- 一次付费调用前，参数必须全部验证完成；失败时不调用 Seedream。调用后不自动重试。返回图片须核验文件和明确要求的比例；视觉质量、中文文字正确性不以文件存在作为验收。
- 工具参数采用一种规范形态。旧 `reference_ids` 仅在迁移期按下文处理，不作为新接口继续扩展。

## 二、规范化字段

顶层工具参数是 JSON 对象，未知字段拒绝。`null` 不等同于省略；除明示允许外均拒绝。字符串去首尾空白后校验；不静默截断 Agent 输出。

| 字段 | 工具 | 必填／空值 | 允许值及含义 | 后端补值或替换 |
|---|---|---|---|---|
| `prompt` | 两者 | 必填；空串、纯空白、单独 ID、`null` 均拒绝 | 完整**视觉设计／修改**指令；编辑时说明改什么、保留什么。不得把讨论稿、未确认选项、素材 ID 当成指令。准确的待生成文案和最终比例以独立字段为准 | 不替写、不截断。只在验证通过后按固定格式追加文字与商品事实；合成后的长度须在服务上限内，否则调用前拒绝 |
| `title` | 仅 `create_image` | 必填；空串和 `null` 拒绝 | 1–120 字的画布作品名；不是图片内文字 | 不代填；不影响 Seedream prompt |
| `asset_id` | 仅 `edit_image` | 必填；空串和 `null` 拒绝 | 真实且存在的画布作品 ID，必须等于 Planning 已绑定的 `targetAssetId` | **不替换**。不相等就拒绝并说明目标不一致；目标作品始终自动作为首张编辑输入图 |
| `references` | 两者 | 必填数组；`[]` 表示**不额外引用图片** | 0–3 个 `{id, role}`，`role` 为 `product`、`style`、`composition` 之一；ID 必须来自本轮已绑定且文件可读的图片；不接收文档 ID | 不从“所有选中素材”自动补齐，不合并旧作品的全部来源。去重或顺序调整也不得静默发生；重复 ID、超量、角色与绑定结果不符均拒绝 |
| `text_mode` | 两者 | 必填；空串和 `null` 拒绝 | `none`：无新增设计文字；`model_render`：让 Seedream 直接生成所列文字。商品本体已有标签不属于新增设计文字 | 不通过 `prompt` 关键词推断或改写 |
| `text_content` | 两者 | 必填数组；`[]` 的含义由 `text_mode` 决定 | 最多 8 条 `{role,text,layout}`；每项均须为非空字符串，`text` 是准确原文，`role` 是层级，`layout` 要说明具体位置、对齐、大小关系和避让 | 不编文案、不改原文、不自动添加默认字体层；仅按固定格式序列化进 Seedream prompt |
| `aspect_ratio` | 两者 | 必填；不允许空串或 `null` | `auto`、`1:1`、`4:3`、`3:4`、`16:9`、`9:16`、`3:2`、`2:3`。`auto`：新图使用服务默认比例；编辑图沿用目标作品实际比例 | 用户本轮或被明确选用的方案有确定比例时，后端预先绑定唯一允许值，Agent 必须照填；不得由后端根据 prompt 中最后出现的数字猜测或静默覆盖 |

`references.role` 的语义：`product` 用于保持商品可见外观，`style` 只借鉴色彩、光线、氛围与材质，`composition` 只借鉴机位或画面组织。编辑目标作品由 `asset_id` 独立表示，不得再填进 `references` 充当 `original`。同一 ID 不得同时承担多个角色；角色不确定时应先澄清或只使用能确定的素材。

`text_content.layout` 可用自然语言，但必须有可执行的版式描述，例如“主标题位于上方 10%–25% 区域、居中、最大字号、避开杯口”。“好看一点”“适当排版”不合格。后端能检查字段非空与长度，**不能靠正则证明版式好坏或文案事实正确**；这仍需 Agent 依据可靠商品信息设计，并在成图后人工／视觉验收。

## 三、字段间关系与冲突处理

1. `text_mode=none` 当且仅当 `text_content=[]`。Seedream prompt 统一追加“无额外设计文字；保留商品本身标签”。Agent 的 `prompt` 不得同时要求新增标题、价格等；发现明确冲突时调用前拒绝，不擅自选一边。
2. `text_mode=model_render` 时 `text_content` 必须有 1–8 条。每条 `text` 是**唯一的准确文案来源**。`prompt` 只写画面与版式意图，不再另写一份不同的文案；后端将 `text_content` 原样序列化一次。若 `prompt` 明确要求无字，或明确写出与 `text_content` 不同的待生成文字，拒绝并要求 Agent 修正。不能声称简单正则可识别所有语义冲突；无法确定时应保守失败，而非付费试错。
3. 有字不等于商品标签有字。只保留杯身、瓶身、包装盒原有印字，仍是 `text_mode=none`；若要新增标题、卖点或价格，必须为 `model_render` 并逐条列出。不得捏造未经确认的功效、价格、优惠和品牌事实。
4. `aspect_ratio` 是**唯一的最终比例字段**。用户本轮明确要求优先于旧方案；若用户指向某一确认方案且本轮没有新比例，采用该方案已绑定的比例；都没有则为 `auto`。Planning／后端先解析和绑定，动态工具 schema 只允许绑定值。Agent 不必在 `prompt` 重复比例；后端用该字段决定 Seedream `size` 并核验成图。`prompt` 若写出相反比例则拒绝，不根据“最后一个比例”决定。
5. `edit_image` 的目标作品不计入 `references` 的 3 张上限；后端传给 Seedream 的首张输入为目标作品，再按 `references` 顺序附参考图，但总输入量须符合供应商限制。若超量，在调用前明确拒绝，不能悄悄丢掉末尾素材。
6. Agent 工具调用必须是合法 JSON 且工具与 Planning 操作一致；每个计划项最多一次付费调用。模型只回复“马上制作”、调用错误工具、或输出非法参数，都不能标记作品已完成。

## 四、旧字段迁移及当前实现差异

当前接口仍使用 `reference_ids: string[]`，它无法表达商品图、风格图的区别。小范围修复后，空数组已不再扩展为所有选中图片，编辑目标也不再自动合并旧参考图。完整新契约拟以 `references: {id,role}[]` 取代它。迁移期若收到 `reference_ids`，只能在**每个 ID 都有唯一、后端已绑定角色**时转换；有任何歧义就拒绝，绝不默认所有图片都是商品图。迁移结束后从工具 schema 和后端删除旧字段。

小范围修复后，`title` 不再代填，`asset_id` 不再替换，参考图不再隐式补入；用户明确的比例通过独立 `aspect_ratio` 核对并决定 Seedream 尺寸。无字数组缺失的兼容补值仍保留，且工具 schema 已将该字段设为可选；完整新契约要求 Agent 明确发送 `[]`，届时需另设清楚的模型纠错路径。素材角色结构化、文字语义冲突检查等其余条款尚未实现。

## 五、schema 与校验如何由同一份契约生成

实现时将上述字段、枚举、长度、必填规则和跨字段规则写成一份**可执行的契约定义**，而不是各写三份文本：

1. 从契约定义生成发给 GLM 的 `create_image` / `edit_image` JSON schema，包括 `required`、`additionalProperties:false`、数组上限、嵌套对象必填项及动态 `asset_id`／`aspect_ratio` 允许值。每个字段生成独立 schema 对象，不共享可被修改的引用。
2. Agent 系统提示词和工具说明引用同一契约中的语义说明与示例；不得另外写一套相反的默认值。提示词帮助模型填写，但**不承担验证职责**。
3. 后端先用同一契约解析并校验工具参数，再运行需要当前项目状态的校验：ID 是否存在、是否已绑定、素材角色是否匹配、目标作品是否一致、文件是否可读、文本／比例是否与明确要求冲突。只有规范化对象通过全部检查才可组装供应商请求。
4. 供应商适配器只做固定映射：`aspect_ratio → size`、目标与参考图片 → 输入图、`prompt + text_content + 已绑定产品事实` → 最终提示词。记录规范化参数及最终请求到 Trace。不能在适配器里重新决定设计或素材角色。
5. 同一契约生成合法与非法样例，测试**实际传给 GLM 的 schema**和**实际运行的后端校验**，不能只对静态 schema 文件做快照测试。schema、提示词与校验改变时应在同一变更中更新。

## 六、Mock 边界清单（均不调用真实付费模型）

**工具可用性与结构**

- 新建计划只提供 `create_image`，编辑计划只提供 `edit_image`；只读任务不提供付费工具。模型只说“正在生成”、选错工具、连续调用两次，均不得产生错误交付或第二次付费请求。
- 实际 GLM 请求里的 schema：`prompt` 不含作品 ID 枚举；`asset_id` 仅含目标作品；`aspect_ratio` 与已绑定比例一致；嵌套字段不因共享对象被联动修改。
- 非法 JSON、非对象、缺字段、`null`、未知字段、错误类型、空白字符串、过长文本与超量数组，均在调用 Seedream 前失败，并给出对应字段的错误。

**文字**

- `none + []` 成功；`none + 缺失数组`、`none + 非空数组`、`model_render + []`、缺失 `text_mode` 均明确失败，不发送付费请求。
- `model_render` 有 1 条和 8 条合法文案成功；第 9 条、缺 `role/text/layout`、空白内容失败。商品本身标签不被误当作新增设计文字。
- `prompt` 写“无字”但 `text_content` 要加标题、或两处准确文案不同：失败；一致时最终 Seedream prompt 只出现一份规范文字清单，不出现默认黑色系统字体指令。

**素材与目标**

- 上传商品图、风格图、构图图各自以正确角色进入请求；空 `references` 确实不额外加图。文档 ID、未绑定 ID、重复 ID、角色冲突、超过上限或文件丢失均在付费前失败。
- 修改时目标作品固定为第一张输入图，不计入参考图数组；错 `asset_id` 不自动改成另一个作品。新作品另存，原作品保留并记录来源。
- 旧 `reference_ids` 只有角色唯一时可迁移；混合素材角色不明时失败，不静默归为商品图。

**比例、组装与交付**

- 本轮明确 `1:1`、只引用方案的 `3:4`、编辑原图未指定比例、用户新要求覆盖旧方案、prompt 与绑定比例冲突，各自得到唯一预期比例或明确失败。
- 核对发给 Seedream 的 `size` 和成图像素比；错误比例的图片不保存为成功作品。不因标题或讨论稿里出现另一个比例就改变最终比例。
- 最终 prompt 保留 Agent 视觉指令，只附固定文字块和已绑定产品事实；不包含 A/B/C 讨论稿、未确认问题或其他商品身份。供应商拒绝、超时和成功但无图片数据均不自动重试、不宣称已交付。

验收标准：以上 Mock 均通过；用最近失败的“改 3:4 为 1:1”和“无字杯子主图”Trace 参数回放，分别得到预期的规范请求或清楚的调用前拒绝；Trace 能指出哪一字段不合契约。真实 Seedream 的中文排版质量仍需单独验收，不属于接口契约通过的证明。
